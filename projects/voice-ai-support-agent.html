Voice AI support agent

Answer the driver support calls that repeat every day, in the language the driver speaks. Send the rest to a person.

Namma Yatri · Central data team · 2024–2025 · Owner, end to end

This is an industry project. The code and the data are proprietary, thus this page shows only the method.

Problem

Drivers called support with the same problems every day. Each call used 15 to 20 minutes of a support agent. The problems repeated, thus the agents gave the same answers again and again. This is not a good use of a support team, and the drivers waited.

Approach

Two models do two different jobs, because neither model is sufficient alone.

How to speak

Gemini Live holds the conversation. It answers in less than one second and it sounds like a person. Latency is important here, because a driver stops a call that pauses.

What to say

The Sarvam models are trained on Indian regional languages. They are stronger than a general model on the words that a driver uses, in Hindi and in Kannada as well as in English.

The agent works in Hindi, English and Kannada. If the agent cannot solve the problem, it sends the call to a person.

Results

The resolution time decreased by approximately 75%. This compares the period after the agent with the period before it, when support agents handled these tickets. The driver NPS (Net Promoter Score) increased by 18 points over the same period.

This is a before-and-after comparison and not a controlled test. The 18 points thus contain the other changes of the period as well as the effect of the agent.

Key insight The generative models were not the difficult part. Gemini Live and the Sarvam models were both strong, and the speech recognition in front of them was not. A voice agent is a chain, and the chain is only as good as its first step. If the agent hears the wrong words, each step after it is wrong, and the driver repeats the sentence to a machine that does not understand.

What went wrong

The hardest part was not the part that looks hardest. Gemini Live and the Sarvam models were both strong. The recognition of the speech was not. The models that recognise Indian regional speech were weaker than the rest of the pipeline, and most of the failures started there. If the agent hears the wrong words, then every step after it is wrong, and the driver repeats the sentence to a machine that does not understand.

What I'd do differently

Improve the recognition layer

The speech recognition is the weakest part of the pipeline and the source of most of the failures. A model that is trained on these speech patterns, or a model that is tuned on the calls, would remove more errors than any change to the generative layers.

A controlled test

Give the agent to a random part of the drivers and keep the others on the human queue. This separates the effect of the agent from the other changes of the period, for the NPS as well as for the resolution time.

Related work

The conversation layer uses the Gemini Live API, which Google made for speech-to-speech conversations with a low latency. The language layer uses the models of Sarvam AI, which are trained on Indian languages. The design of this project is a division of labour between the two.

Code & artifacts

The code is proprietary to Namma Yatri. Stack: the Gemini Live API for the conversation and the speech, the Sarvam models for the Indian languages, intent definitions for the repeated support problems, and a handoff to the human support queue.
